# Перевод «The Road to Unfreedom» Т. Снайдера на белорусский язык

Проект: перевод книги Timothy Snyder «The Road to Unfreedom» (2018) на
белорусский язык с трёх источников: английский оригинал, украинский перевод
(Г. Герасим, «Човен», 2020), русский перевод.

## Исходные файлы — НИКОГДА НЕ ИЗМЕНЯТЬ

- `The Road to Unfreedom by Timothy Snyder_EN.epub` — английский оригинал
- `The Road to Unfreedom by Timothy Snyder_UA.pdf` — украинский перевод
- `The Road to Unfreedom by Timothy Snyder_RU.epub` — русский перевод
- `sources/EN.md`, `sources/UK.md`, `sources/RU.md` — извлечённый из них
  текст (генерируются `extract_sources.py`); вручную не редактировать.

## Язык и типографика перевода

- Белорусский язык, **официальная орфография** (правила 2008 г., «наркомовка»,
  не тарашкевица): «снег», «не» и «без» всегда через «е» (не «ня», «бяз»),
  ассимилятивная мягкость НЕ обозначается («свет», не «сьвет»).
- Кавычки — только «ёлочки»: « ». Вложенные кавычки: „ “.
- Тире — длинное (—), с пробелами с обеих сторон; диапазоны — без пробелов
  (1930—1940-я).
- Апостроф — типографский ’ (U+2019): «аб’ект», «з’явіцца», «сям’я».
- Буква «ў» обязательна по правилам; «і»/«й» по правилам чередования.
- Имена собственные — по белорусским правилам передачи иностранных имён:
  автор — **Тымаці Снайдэр**; аканье и яканье в передаче, дзеканье/цеканье
  (Дзмітрый, не Дмитрий). Сверяться с глоссарием `work/<part>/<model>/glossary.md`.

## Иерархия источников (ОБЯЗАТЕЛЬНА для synthesizer и рецензентов)

1. **EN — авторитетный источник смысла, структуры и модальности.**
   Что сказано, в каком порядке, с какой степенью уверенности (may/must/
   probably/seems) — определяется ТОЛЬКО по английскому тексту. Число и
   границы абзацев BY = числу и границам абзацев EN.
2. **RU — авторитетный источник для цитат русскоязычных авторов** (Ильин,
   Путин, Сурков, Дугин, Гиркин и др.), русских реалий, имён и топонимов:
   эти цитаты в RU, вероятно, даны по оригиналу, а не переведены обратно
   с английского. В таких местах переводим цитату с русского текста;
   UK — второй источник; EN — контроль смысла (что именно процитировал
   Снайдер и в каком объёме).
3. **UK — подсказка по естественности, идиоматике, синтаксису.** Украинский
   перевод показывает, как близкородственный язык решил проблему, не
   копируя русских конструкций. Но украинские слова и формы НЕ переносить.
4. **RU лексика и синтаксис вне цитат — НЕ образец.** ГЛАВНАЯ ОПАСНОСТЬ
   пайплайна — русизмы, кальки и пословное переложение с русского.
   Вторая опасность — украинизмы. См. скилл `belarusian-style`.

## Имена файлов

- Готовый перевод части (в корне репозитория):
  `The_Road_to_Unfreedom_by_Timothy_Snyder_<Model>_<N>_BY.md`,
  где `<Model>` = `Fable` или `Opus`, `<N>` — номер части:
  `0` = пролог, `1`—`6` = главы, `7` = эпилог.
- Рабочие файлы: `work/<part>/<model>/...`, где `<part>` ∈
  {`prologue`, `ch1`…`ch6`, `epilogue`}, `<model>` ∈ {`fable`, `opus`}:
  - `segments.md` — выровненная таблица ID | EN | UK | RU (split_align.py);
    только для synthesizer
  - `segments_EN.md`, `segments_UK.md`, `segments_RU.md` — те же абзацы по
    одному языку (механическая изоляция одноязычных агентов)
  - `align_report.md` — отчёт о расхождениях выравнивания
  - `glossary.md` — глоссарий (terminologist)
  - Каждый субагент пишет ТОЛЬКО в файлы своего фрагмента `f<NN>` (f01, f02…) —
    общих файлов агенты не трогают, поэтому любые вызовы можно распараллеливать:
    - `draft_A_f<NN>.md` (с EN), `draft_B_f<NN>.md` (с UK), `draft_C_f<NN>.md`
      (с RU) + `summary_A_f<NN>.md` и т.п.
    - `draft_D_f<NN>.md` — синтез фрагмента;
      `draft_D_round<k>_f<NN>.md` — фрагмент после ревизии раунда k
    - `reviews/round-<k>/<reviewer>_f<NN>.md` — замечания рецензентов
    - `decisions_round<k>_f<NN>.log` — решения синтезатора по фрагменту
  - Склейка — обязанность оркестратора (после завершения всех фрагментов):
    `draft_A.md`, `draft_B.md`, `draft_C.md`, `draft_D.md` (конкатенация
    фрагментов по порядку ID), `decisions.log` (конкатенация фрагментных
    логов)

## Формат готового файла *_BY.md

Абзац «чистого» файла — одна строка; затем `justify.py` даёт строки ровно
≤ 85 символов Unicode с выключкой (см. `.claude/skills/md-justify/`).
Проверка — `check_format.py`; hook `check_by_format.py` автоматически
проверяет каждый записанный `*_BY.md` в корне. Число абзацев BY = числу
абзацев EN той же части.

**Не баг:** при рендеринге Markdown (GitHub и др.) кратные пробелы
схлопываются в один, поэтому выключка по 85 символов видна только в Raw-виде
файла (или в редакторе/`cat`). Рендер покажет «обычный» текст — это
ожидаемо, формат проверяется по исходнику.

## Скрипты (Python 3, только стандартная библиотека)

Все в `.claude/skills/md-justify/scripts/`, запускать из корня репозитория:

```bash
python3 .claude/skills/md-justify/scripts/extract_sources.py        # sources/*.md
python3 .claude/skills/md-justify/scripts/split_align.py --part prologue --model fable
python3 .claude/skills/md-justify/scripts/justify.py clean.md -o out_BY.md
python3 .claude/skills/md-justify/scripts/check_format.py out_BY.md --part 0
```

## Процедура перевода

Полная процедура — в скилле `translation-pipeline`. Кратко: главная сессия —
оркестратор; субагенты НЕ вызывают друг друга. Подготовка → глоссарий →
черновики A/B/C параллельно → синтез D → раунды рецензий (fidelity +
interference + language [+ back-translation]) → ревизия; стоп, когда нет
critical/major, максимум 3 раунда → сборка justify.py → check_format.py →
коммит. Все промежуточные артефакты сохраняются в `work/`.
