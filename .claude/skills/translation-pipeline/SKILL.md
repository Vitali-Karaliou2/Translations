# Пайплайн перевода части книги

Главная сессия — ОРКЕСТРАТОР. Все субагенты (`.claude/agents/`) вызываются
только оркестратором; субагенты НЕ вызывают друг друга. Перед началом
прочитай CLAUDE.md и `.claude/skills/belarusian-style/SKILL.md`.

Параметры запуска: `<part>` (prologue|ch1…ch6|epilogue), `<model>`
(fable|opus), `<N>` (0…7 для имени файла), `<Model>` (Fable|Opus).

## Шаг 0. Подготовка

```bash
# если sources/*.md ещё нет:
python3 .claude/skills/md-justify/scripts/extract_sources.py
python3 .claude/skills/md-justify/scripts/split_align.py --part <part> --model <model>
```

Прочитай `work/<part>/<model>/align_report.md`. Все расхождения EN/UK/RU
отметь: для абзацев, где UK или RU разбиты иначе, при раздаче фрагментов
передавай объединённые ячейки сегментов как есть (строка таблицы = один
абзац EN = один абзац BY).

## Шаг 1. Глоссарий

Вызови **terminologist** (один раз на часть): вход segments.md, выход
`glossary.md`. Проверь раздел «Цитаты»: каждый абзац с цитатой
русскоязычного автора должен быть в нём перечислен.

## Шаг 2. Черновики A, B, C — параллельно

Раздели часть на фрагменты по 5–8 абзацев и пронумеруй их: f01, f02…
Каждый вызов агента пишет ТОЛЬКО в файлы своего фрагмента
(`draft_A_f<NN>.md` и т.п.), поэтому параллелить можно и переводчиков
между собой, и фрагменты. Для каждого фрагмента вызывай ПАРАЛЛЕЛЬНО
(в одном сообщении) трёх переводчиков, сообщая каждому его номер NN:

- **translator-en** → draft_A_f<NN>: передай в промпте ТОЛЬКО EN-тексты
  абзацев фрагмента (ID + текст) либо диапазон ID + путь к `segments_EN.md`,
  путь к глоссарию и summary предыдущего фрагмента (`summary_A_f<NN-1>.md`);
- **translator-uk** → draft_B_f<NN>: только UK-тексты / `segments_UK.md`;
- **translator-ru** → draft_C_f<NN>: только RU-тексты / `segments_RU.md`.

Если фрагменты идут параллельно, summary предыдущего фрагмента ещё нет —
тогда передай вместо него 1–2 предложения контекста от себя (что было в
предыдущих абзацах по segments.md).

Когда все фрагменты готовы, склей `draft_A.md`, `draft_B.md`, `draft_C.md`
из фрагментных файлов по порядку ID (конкатенация; проверь, что каждый ID
встречается ровно один раз).

НИКОГДА не передавай переводчику тексты чужих языков и путь к общему
`segments.md` (в нём все три языка в каждой строке) — чистота эксперимента
и качество синтеза зависят от независимости черновиков. Единственная
настоящая изоляция — не давать агенту того, чего он не должен видеть:
одноязычным агентам указывай только их `segments_<LANG>.md`;
be-language-editor и back-translator — только белорусские абзацы draft_D
(лучше прямо в промпте), без путей к источникам.

## Шаг 3. Синтез D

Для каждого фрагмента вызови **synthesizer** (раунд 1): он читает
segments.md, глоссарий, A/B/C и пишет `draft_D_f<NN>.md`. Передай ему номер
фрагмента NN, диапазон ID и summary предыдущего фрагмента. Вызовы по разным
фрагментам можно параллелить. Затем склей `draft_D.md` по порядку ID.

## Шаг 4. Раунды рецензий (k = 1, 2, 3)

На каждом раунде вызови ПАРАЛЛЕЛЬНО (фрагментами по 5–8 абзацев, сообщая
каждому k и NN):

- **fidelity-reviewer** — EN↔BY (+RU для цитат);
- **interference-reviewer** — BY↔RU(+C) и BY↔UK;
- **be-language-editor** — только BY + глоссарий;
- опционально (рекомендуется минимум в одном раунде для пролога/глав с
  цитатами): **back-translator**, затем сам сравни его BY→EN с оригиналом
  и добавь найденные расхождения в собственный файл замечаний
  `reviews/round-<k>/orchestrator_f<NN>.md` (той же таблицей).

Замечания пишутся в
`work/<part>/<model>/reviews/round-<k>/<reviewer>_f<NN>.md`
таблицей `| ID | серьёзность | фрагмент | предложение | обоснование |`.

Затем вызови **synthesizer** (ревизия) по каждому фрагменту (можно
параллельно): он применяет/отклоняет замечания и пишет
`draft_D_round<k>_f<NN>.md` + `decisions_round<k>_f<NN>.log`. После раунда:
склей новую версию `draft_D.md` из `draft_D_round<k>_f<NN>.md` и допиши
`decisions.log` конкатенацией фрагментных логов раунда.

**Критерий остановки**: в последнем раунде нет замечаний critical и major —
стоп. Максимум 3 раунда; если после 3-го остались critical — отметь их в
отчёте как спорные места.

## Шаг 5. Сборка и проверка

1. Собери «чистый» файл: заголовок части + абзацы draft_D по порядку ID
   (абзац = одна строка, между абзацами пустая строка).
2. ```bash
   python3 .claude/skills/md-justify/scripts/justify.py <clean> -o The_Road_to_Unfreedom_by_Timothy_Snyder_<Model>_<N>_BY.md
   python3 .claude/skills/md-justify/scripts/check_format.py The_Road_to_Unfreedom_by_Timothy_Snyder_<Model>_<N>_BY.md --part <N>
   ```
3. Запуск check_format.py в п. 2 ОБЯЗАТЕЛЕН — justify.py пишет файл через
   Bash, и PostToolUse-hook этого не видит. Страховка: Stop-hook проверяет
   все `*_BY.md` в корне при каждой остановке сессии и заблокирует
   завершение, пока ошибки не исправлены.

## Шаг 6. Коммит

A, B, C, D, глоссарий, все рецензии, decisions.log и готовый файл —
закоммить и запушь в рабочую ветку (без --force):

```bash
git add work/<part>/<model> The_Road_to_Unfreedom_by_Timothy_Snyder_<Model>_<N>_BY.md
git commit -m "Translate <part> to Belarusian (<Model>)"
git push -u origin <branch>
```

## Шаг 7. Отчёт

В конце выдай краткий отчёт:
- число раундов рецензий;
- статистика замечаний по рецензентам и серьёзности (по файлам reviews/);
- спорные места (отклонённые замечания, оставшиеся critical);
- сколько решений принято в пользу каждого источника — посчитай по полю
  `source=` в decisions.log (EN/UK/RU/BY-стиль); перед подсчётом убедись,
  что все `decisions_round<k>_f<NN>.log` склеены в decisions.log.
